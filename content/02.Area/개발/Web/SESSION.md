# SESSION 세션 

SESSION은 [JWT(Json Web Token)](JWT(Json%20Web%20Token).md)과 같이 비연결성(Connectionless)을 가진 HTTP에서 사용자를 인증하기 위한 주요 방법 중 하나입니다.

세션은 JWT와 달리 서버에서 상태 정보를 관리하며, `JSESSIONID`와 같은 특정한 세션 ID를 생성하여 사용자를 인증하고 관리합니다.

사용자가 `LOGIN` 요청을 하면, [WAS(Web Applicatoin Server)](WAS(Web%20Applicatoin%20Server).md) 는 사용자의 인증 정보를 기반으로 **세션 ID**를 발급하고 이를 서버에 저장합니다. 발급된 세션 ID는 클라이언트의 쿠키(Cookie)에 저장되며, 이후 클라이언트는 요청마다 이 세션 ID를 서버에 전달합니다.

## **세션의 동작 과정**

1. **로그인 요청 및 세션 ID 발급**
    
    - 사용자가 `LOGIN` 요청을 보내면, WAS는 인증 정보(예: 사용자 ID, 비밀번호)를 확인합니다.
    - 인증 성공 시, WAS는 고유한 **세션 ID**를 생성하고 이를 서버에 저장합니다.
    - `HTTP 헤더의 SET-COOKIE`를 통해 세션 ID가 클라이언트의 쿠키에 저장됩니다.
    
    ![로그인 시 세션 ID 발급](https://file-api.ksq9511.synology.me:5353/obsidian-image/20241226041201.png)
    
2. **사용자 인증 요청**
    
    - 인증이 필요한 요청 시, 클라이언트는 이전에 저장된 세션 ID를 쿠키와 함께 서버로 전송합니다.
    - WAS는 서버에 저장된 세션 정보와 클라이언트로부터 전달받은 세션 ID를 비교하여 유효성을 검증합니다.
    - 검증 성공 시, 서버는 클라이언트에게 적절한 응답을 보냅니다.
    
    ![세션 인증 과정](https://file-api.ksq9511.synology.me:5353/obsidian-image/20241226041876.png)

## **SESSION VS COOKIE**

세션과 쿠키는 HTTP의 무상태성을 극복하여 사용자 상태를 유지하는 데 사용되며, 저장 및 관리 주체에 따라 차이점이 있습니다.

- **세션(Session)**:  
    서버에서 상태를 관리합니다. 사용자의 인증 정보가 서버에 저장되며, 클라이언트는 이를 참조하기 위한 세션 ID만 서버로 전달합니다.
    
- **쿠키(Cookie)**:  
    클라이언트에서 상태를 관리합니다. 서버가 직접 사용자 상태를 저장하지 않고, 필요한 정보를 클라이언트 쿠키에 저장해 매 요청마다 서버로 전달합니다.


## **세션과 JWT의 차이**

1. **관리 주체**
    - 세션: 서버가 상태 정보를 관리합니다. 서버가 종료되거나 세션이 만료되면 인증 상태를 복구하려면 재로그인이 필요합니다.
    - JWT: 클라이언트가 인증 정보를 직접 보유합니다. 서버의 상태와 독립적으로 작동하며, 서버가 종료되더라도 JWT 자체가 유효하면 인증이 가능합니다.
2. **서버 부하**
    - 세션: 서버는 사용자의 세션 정보를 메모리나 저장소에 유지해야 하므로, 동시 접속자가 많아질수록 부하가 증가합니다.
    - JWT: 클라이언트가 정보를 유지하므로 서버는 상태를 관리할 필요가 없어 확장성이 뛰어납니다. 단, JWT 크기가 커질 경우 네트워크 부하가 증가할 수 있습니다.
3. **보안**
    - 세션: 세션 ID는 암호화된 상태로 쿠키에 저장되며, 서버에 민감한 정보를 유지합니다.
    - JWT: 자체적으로 서명되어 변조를 방지하지만, 클라이언트에 저장되므로 민감 정보는 포함하지 않아야 합니다.

## **세션과 쿠키의 차이점 정리**

|구분|쿠키 (Cookie)|세션 (Session)|
|---|---|---|
|**저장 위치**|클라이언트(브라우저)|서버|
|**보안 수준**|낮음 (클라이언트에 저장되기 때문)|높음 (서버에 민감 정보 저장)|
|**유지 기간**|설정된 만료 시간까지 유지 (영구적 가능)|기본적으로 브라우저 종료 시 만료|
|**데이터 용량**|제한적 (보통 4KB 이하)|제한 없음 (서버 메모리/디스크 용량에 따라 다름)|
|**성능**|클라이언트가 상태 정보를 관리하므로 서버 부하 적음|서버에서 관리하므로 동시 접속자 증가 시 부하가 큼|
|**확장성**|뛰어남 (서버 상태와 독립적)|제한적 (서버에 부하가 직접적으로 영향)|
