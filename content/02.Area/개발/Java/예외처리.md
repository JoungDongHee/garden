# 예외 처리가 필요한 이유

프로그래밍에서  예외 처리는 중요하다. 그리고 이 예외처리를 얼마나 잘하냐에 따라 프로그래머의 역량 이 결정된다.


# 예외 상황

예외 처리 는 문자 그대로 의 의미 이다. 무언가 `예외` 에 대한 상황이 발생했을때 이를 `처리`해주는 것을 의미 한다.

``` java
package exception;  
  
public class test {  
    public static void main(String[] args) {  
        String test = "test";  
        int i = Integer.parseInt(test);  
        System.out.println(i);  
    }  
}
```

^c0e19c

위 코드를 실행 해볼 경우 `String` 문자 열을 `Integer` 의 parseInt 메소드를 활용하여 숫자로 변환 시킬려고 하였다. 

하지만 실제로는 다음과 같은 메세지 와 함께 프로그램이 종료가 되었다.


> [!danger] Error
> Exception in thread "main" java.lang.NumberFormatException: For input string: "test"
> 	at java.base/java.lang.NumberFormatException.forInputString(NumberFormatException.java:67)
> 	at java.base/java.lang.Integer.parseInt(Integer.java:661)
> 	at java.base/java.lang.Integer.parseInt(Integer.java:777)
> 	at exception.test.main(test.java:6)


test 는 문자이기 때문에 `숫자로 변환` 을 할수 없다. 

그렇기 때문에 프로그램은 이를 에러 혹은 오류라고 보고 프로그램을 강제 종료 한 것이다.이러한 프로그램의 강제 종료를 방지하기 위해 예외 처리를 사용해줘야한다.

# 기본적인 예외처리

[ 해당 코드](%EC%98%88%EC%99%B8%EC%B2%98%EB%A6%AC.md#^c0e19c) 에서 발생한 문제를 예외 처리하여 해결하면 다음과 같다.

발생한 예외 `NumberFormatException` 을 `catch` 에서 정상적인 로직으로  `int defaultValue = 0;` 되도록 대체값을 사용하여 반환하거나 사용한다.

```java
public class ExceptionExample {
    public static void main(String[] args) {
        try {
            String test = "test";
            int i = Integer.parseInt(test);
            System.out.println(i);
        } catch (NumberFormatException e) {
            // 로깅
            logger.error("숫자 변환 실패: {}", test, e);
            // 사용자에게 알림
            System.out.println("올바른 숫자를 입력해주세요.");
            // 대체 값 사용
            int defaultValue = 0;
            // 또는 재시도 로직
            retryOperation();
        }
    }
}
```


# 예외 처리 이유

예외 처리를 하는 이유는 무엇일까? 이유는 간단하다 프로그램을 종료하지 않고 `예외` 상황에 대해 대응하여 프로그램이 정상적으로 동작하기 위함 이다.

프로그램은 사람이 만들며 사용자 또한 사람이 사용한다. 모든 상황에 대해 가정하여 프로그램을 만들면 좋겠지만 알수없는 상황 과 또는 다른 프로그램의 오류로 인해 `예외` 가 발생할수 있다. 

이때 마다 프로그램이 종료 된다는건 `치명적인 결함` 이 아닐수 없다.


- **프로그램의 안정성 확보**
    - 예측하지 못한 상황에서도 프로그램이 정상적으로 동작
    - 시스템 자원의 적절한 정리와 반환 보장
- **사용자 경험 향상**
    - 프로그램 충돌 대신 적절한 에러 메시지 제공
    - 복구 가능한 상황에서는 대체 로직 실행
- **디버깅 및 유지보수 용이성**
    - 문제 발생 시 정확한 원인 파악 가능
    - 로깅을 통한 시스템 모니터링
